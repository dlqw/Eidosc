# Eidosc 0.5.0-alpha.1

## Eidos 0.8 language support

- Added implicit function bodies when the first runtime parameter normalizes to `Unit`.
- Added canonical `Bool`, `Option`, `Result`, and right-biased `Either` branch selection with arm-local `_0`, `_1`, and later payload placeholders.
- Lowered branch selection to ordinary `match` in HIR and added formatter, diagnostics, conservative migration actions, CTFE, generated-source mapping, and LSP language-intelligence support.
- Restricted the compiler's active language version to `0.8.0-alpha.1` while retaining `legacy`, 0.5, 0.6, and 0.7 only as explicit migration inputs.

## Metaprogramming and build host

- Added typed CTFE, value-level const generics, compiler-owned reflection, derive/expansion protocols, stable generated documents, and deterministic metaprogramming budgets and cache identities.
- Added capability-constrained `[build]` programs, canonical `BuildGraph` validation/execution, declared input and output tracking, generated-source integration, and build graph tracing.

## Tooling and Windows LSP

- Fixed percent-encoded Windows drive URI handling and canonicalized existing on-disk file-name casing so a stale `Main.eidos` URI no longer causes a false naming diagnostic for `main.eidos`.
- Updated compiler, release automation, Eidosup guidance, compatibility metadata, and embedded Std metadata for the independently versioned Eidos 0.8 ecosystem.
- Updated the pinned tutorial release smoke fixture to Eidos `0.8.0-alpha.1` and added an early manifest compatibility preflight so stale language fixtures fail before multi-platform bundle publication.
- Isolated release smoke builds in a minimal generated project so unrelated tutorial-wide FFI link dependencies cannot contaminate clean-install or published-install verification.

## Native ownership and sequence reuse

- Added compiler-owned caller storage for eligible aggregates, path-sensitive escape proofs, balanced drop insertion, unique-owner record and sequence updates, read-only range fusion, and inline sequence header/data lowering.
- Preserved copy-on-write behavior for shared values while allowing proven unique values to reuse backing storage across branches, loops, projections, and calls without requiring a separate user-facing container API.
- Fixed caller-owned containment escape analysis with CFG provenance fixed points and field-path sensitivity so aggregates contained by returned values remain heap-backed when required.

## Recursion, inlining, and constant calls

- Added the linear-recursion accumulator transform for the proven Fibonacci recurrence shape, retaining metadata, ownership, effect, type, CFG, and unchecked-overflow equivalence.
- Enabled MIR inlining for strictly proven single-block callees and hardened generic, runtime-word, caller-owned, trait, constructor, borrow, closure, move, temporary-id, and metadata boundaries.
- Added pure constant-call folding with structured memoization, recursive-cycle detection, copy propagation, and a deterministic shared semantic budget that terminates on empty control-flow and constant-switch loops.

## LLVM call contracts and required gates

- Added greatest-fixed-point `nounwind` inference for the complete internal call graph and scalar `noundef` parameter attributes while conservatively excluding unresolved, indirect, FFI, and runtime-word ABI boundaries.
- Preserved function, call-site, parameter, calling-convention, fragment, and fingerprint attributes across full and incremental LLVM emission.
- Added required Windows and Ubuntu shards for call folding, recurrence proofs, MIR inlining, caller-owned escape analysis, LLVM attributes, native checksum equivalence, allocation counts, and Ubuntu AddressSanitizer stack-lifetime validation. Required shards fail when their filter selects zero tests.

## Measured performance

- On Windows x64 with `-O3 --native-cpu --lto`, the 5,000,000-step Snake benchmark improved from 319.89 ms before the native ownership series to 124.69 ms, with checksum `2094999808` unchanged and zero steady-state allocation growth after warmup.
- A repeated non-tail Fibonacci workload improved from 44.323 ms to 31.054 ms, while iterative and already tail-call-eliminated forms remained within measurement noise.
- The profiled MIR phase reduced cumulative managed allocation from 665.07 MiB to 412.14 MiB; the specialization loop reduced allocation from 308.26 MiB to 54.53 MiB.

## Compatibility

- Eidos language: `>=0.8.0-alpha.1 <0.9.0`
- Eidos Std: `0.2.0-alpha.1`
- Manifest schema: `3`
