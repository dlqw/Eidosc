# Lex underscore-prefixed identifiers as single tokens

- The scanner dispatched `_`-initial tokens through the single-character wildcard rule
  unless the next character was a digit, so `_x`/`__x` lexed as `_` + `x` and produced
  confusing E4001/E3000 diagnostics instead of identifier resolution (issue #80).
- Any `_` followed by an identifier-continuation character now routes through the
  identifier rules: `_x`, `_0` and `__x` are single identifiers, a bare `_` remains the
  wildcard token, and the compiler-reserved `__` prefix now reports its dedicated E3055
  diagnostic instead of a parse cascade.
- Adds `IdentifierLexingTests` covering all three cases.
