# Module-level mutable variables: HIR retention + MIR storage

- Lower module-level `mut name := expr;` bindings through MIR: `MirModule.ModuleVars` carries each module-level mutable variable (name, symbol, runtime type, constant initializer), and variable reads/writes lower to `MirPlace { Kind = ModuleVar }` operands for `MirLoad`/`MirStore`. This is stage 2 of plan `eidos-module-level-mutable-globals-design-2026-08-13`; the previous `E5001` MIR fallback is gone.
- Initializers must be compile-time literals (integer/float/string/char/bool/unit, or negated numeric literals); anything else reports `E5301`. LLVM global lowering and end-to-end codegen remain the stage 3 follow-up, so full `build` stops at the LLVM phase with the existing unsupported-place-kind diagnostic.
- MirValidator, MirFormatter, module fingerprints, convergence hashes, optimizer module cloning, and module MIR state payload round-trips now carry module-variable metadata.
