# C2E: whole-project pipeline with cross-TU resolution and a semantic compile gate

Moves C2E from per-TU probes toward hands-off project translation. The
driver gains `--project` mode:

- **Two-pass cross-TU resolution**: pass 1 translates each TU and exports the
  Eidos signatures of successfully translated functions; pass 2 re-translates
  with that manifest so calls into other TUs invoke the translated function
  directly (same merged module) instead of falling back to `extern(c)` floor
  stubs. Signature conflicts (same name, different types) drop out of the
  manifest and fall back to extern.
- **Bucketed block merge**: all TU outputs merge into one `Raw :: module` in
  declaration-before-use order (imports → records → externs → module globals
  → function bodies), with identical blocks deduplicated across TUs and
  same-name/different-body functions logged as conflicts (first wins). Block
  splitting uses a column-0 rule — blank lines only separate blocks when the
  previous non-empty line is unindented, because statement blocks leave
  internal blank lines.
- **Package emission**: `eidos.toml` (library target, `[ffi]` floorSymbols,
  nativeSources, linkerFlags passthrough), merged native shims, floor symbol
  manifest.
- **Semantic compile gate**: the merged module runs through
  `CompilationPipeline` (Types phase by default, `--gate-phase Llvm` for the
  full backend) with line-annotated diagnostics written to
  `gate_diagnostics.txt`. This converts "translation count" into "usable
  count" — the regex metric overstates accessor-heavy output, and
  translated-but-not-compiling code was invisible before.

Running the gate over raylib's four real TUs (rcore/rshapes/rtext/rtextures,
desktop/GL33 config) drove the merged-module error count from a broken parse
cascade to **105 type-level errors across 624 translated functions**, which
is the honest remaining backlog. Fixes landed along the way, each uncovered
by the gate:

- **Large integer literals**: C unsigned 32-bit constants (2864434397 =
  0xAABBCCDD) exceed the lexer's default Int32 parse; literals outside the
  i32 range now emit with the Int64 suffix `l` (also in switch case values).
- **Keyword collisions**: Eidos reserved words colliding with C identifiers
  broke parsing (raylib's `AudioStream.type` field, raymath's `fn` local for
  far-near). Fields, locals, parameters, and module globals now sanitize
  consistently (suffix `c2e`) with declaration/reference co-rename;
  accessor C symbols keep the original names.
- **Multi-word record spellings**: `RecordNameFromSpelling` stripped only
  one prefix word, so `const struct Vector2` left `struct Vector2` as a
  record name and emitted `c2e_struct Vector2_x_get` (space inside the
  identifier). It now loops over struct/union/enum/const/volatile.
- **System-header inline functions** (UCRT math): skipped from translation
  *and* from the translatable-candidate set — leaving them in candidates made
  calls route through the internal direct-call path, emitting bare names for
  bodies that were never emitted.
- **Enum constants** (LOG_INFO, RL_PIXELFORMAT_*, ...) are now collected and
  emitted as module-level bindings when used.
- **Unmappable globals** (static lookup tables like `stb__perlin_randtab`,
  `rprand_state`): references now skip the containing function honestly
  instead of emitting undefined bare names.
- Function bodies are blank-line separated in translator output so the merge
  can distinguish adjacent functions.

Remaining known gaps from the gate's error list (next session's backlog):
call-argument and return type mismatches around RawPtr/Int (pointer-int
arithmetic patterns), bitwise operands on non-Int, and static array globals
(which should map to module-level calloc buffers rather than skip).
