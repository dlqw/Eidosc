# Borrow checker: liveness-gated borrow ending, inline borrow bindings, Seq-owned projections

Makes the `projects/ecc` template compile for the first time (201 borrow
errors → 0; both `EccMainTemplate_*` gates now pass) via three root-cause
fixes in ownership analysis rather than source migration.

## Liveness-gated borrow ending (183 MutateWhileBorrowed false positives)

Self-recursive tail calls lower to loops (`store %1, rest; goto bb1`), and
match-guard evaluation creates load aliases (`%15 = load %1[0]._0; %17 =
load %15`) that nothing ended: the borrower temp was never consumed or
dropped, so alias state rode the back-edge and the next iteration's
redefinition of the borrowee was flagged as MutateWhileBorrowed.

`LoanConstraintVerifier` now ends borrows whose borrower is provably dead at
the write point (block scan: redefinition-before-use kills the old value;
otherwise LivenessAnalyzer LiveOut decides; conservative when liveness is
absent) before reporting conflicts. `IndexedBorrowState` gains a
predicate-based `EndBorrowsByBorrowee`; the pipeline passes the function's
liveness analysis into the verifier.

## Inliner: Ref parameters bind by borrow, not move (8 move-chain errors)

Inlining `current_parent_active(ref frames)` materialized the Ref parameter
as `%73 = move %18`, consuming ownership the source only borrowed — the
later real move became DoubleMove/UseAfterMove. The inliner now mirrors
MirBuilder's ref-argument preparation: parameters whose type resolves to
Ref/MutRef bind via a borrow-alias `MirLoad` instead of a `MirMove`
(`MirOptimizer.CreateDefault` accepts an `isBorrowType` resolver; the
pipeline supplies one backed by the HIR type-descriptor table).

## Reliable Seq discriminator: index projections are owned copies (4 errors, plus latent debt)

`RuntimeArray.push(result)(xs[index])` with non-Copy elements reported
NeedOwnershipButBorrowed: #84 marked every non-Copy projected load a borrow
alias. That is right for owning aggregates but wrong for Seq indexing —
the runtime semantics of a non-alias element load is load + IncRef
(an independent reference), and codegen already emits exactly that.

`MirBuilder` now carries a reliable discriminator: the builtin Seq type
constructor is resolved once through the symbol table
(`LookupType("Seq")` → `TypeConstructorKey.FromSymbol`), then matched
against the descriptor table and dynamic type keys with a negative-result
cache. Seq-index projections therefore skip the borrow-alias policy.
The #84 aggregate-projection strictness (e.g. `second(rec.field)`
captures) still reports as before — `generic_nonzero_partial_deref_
noncopy_error.eidos` still passes; the Seq-index counterpart fixture
`generic_nonzero_partial_dynamic_index_noncopy_error.eidos` moved to
`borrow/valid/generic_nonzero_partial_dynamic_index_seq_owned_ok.eidos`
(the program is now legitimately accepted: the partial application
captures an IncRef'd owned element).

Known follow-up: the same `xs[index]`-into-owned-position shape exists in
other stdlib loops (folds, count, exists — elements passed by value); they
now compile via the same owned-load semantics, but deserve an audit for
refcount-cost and consistency.
