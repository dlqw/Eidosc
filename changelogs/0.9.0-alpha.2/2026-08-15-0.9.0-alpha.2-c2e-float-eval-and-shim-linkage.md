# C2E: correct float literal evaluation and accessor shim linkage

- `CBodyTranslator.EvaluateLiteral` evaluated floating-point literals through
  `clang_EvalResult_getAsStr`, which the clang-c API defines only for non-Int/Float
  result kinds; on a Float result this libclang build returns the double's raw bit
  pattern as a `char*` (e.g. `10.0` → `0x4024000000000000`), so marshaling it as a
  string raised `System.AccessViolationException` and killed the test host.
  Float literals now evaluate via `clang_EvalResult_getAsDouble` (new
  `EvalResultGetAsDouble` export in `ClangNative`) and render with the invariant
  round-trip format; non-Float kinds are skipped with a reason instead of
  triggering undefined behavior.
- Record-member accessor shims (`c2e_<Record>_<member>_get/set`) were emitted as
  `static` C functions — internal linkage made them invisible at link time
  (`lld-link: undefined symbol`) because the Eidos side references them from a
  different object. The shims now use external linkage, matching the
  `extern(c)` declarations the translator generates.
- `C2E_UnionMemberBridge_ParityWithClang` could never pass as merged: the parity
  helper deleted the temp `input.c` before the shim (which `#include`s it by
  absolute path) was compiled, and the hard-coded exit-code assertion (148) was
  derived from a non-overlapping union model. The test now keeps the input file
  alive until after the native run and asserts the actual aliasing result (100:
  5.5/12.5 doubles have zero low 32 bits, so `radius` reads 0; second call adds
  100), which the clang reference agrees with.
