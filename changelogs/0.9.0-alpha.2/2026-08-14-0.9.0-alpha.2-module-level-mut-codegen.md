# Module-level mutable variables: LLVM global lowering and codegen

- Complete stage 3 of plan `eidos-module-level-mutable-globals-design-2026-08-13`: `MirModule.ModuleVars` now lower to LLVM data globals (`@eidos_g_<module>_<name> = global <type> <const>`), and `PlaceKind.ModuleVar` reads/writes emit `load`/`store` against the global. Scalar constant initializers are lowered directly; managed runtime initializers report `E5302`.
- The name-first parser now recognizes `name := expr;` inside a function body as an assignment when `name` is a module-level mutable binding declared earlier in the same module (previously the ambiguous form parsed as a fresh local immutable binding). This closes the write-path gap so `counter := counter + 1; counter` actually stores to the global and a later call observes the updated value.
- End-to-end gates: the module-level mutable counter probe compiles to native and returns 2 after two increments; LLVM IR integration coverage asserts global definition plus `load`/`store @global`.
