# Union member views and tagged-union ADT bridging

Design position (roadmap §8.0): C unions are untagged overlapping storage and Eidos ADTs are
tagged sum types — no representation-level mapping exists. Conversion is semantic and sound
only where C code maintains its own tag. Delivered in two bindgen layers:

## M4a — union member views (zero compiler changes)

- `pkg bind` replaces the "unions are not representable" SKIP with per-union layout constants
  (`{u}_size`/`{u}_align`) and shim-backed member accessors: scalar and pointer members get
  value get/set (`{u}_{m}_get :: RawPtr -> T`, `{u}_{m}_set`), aggregate members get an
  address-of getter (`RawPtr`). enum members widen through `int64_t`/`Int` shims.
- std.Ffi pointer intrinsics are `compiler(internal)` and unavailable to generated code, so
  accessors lower through the auto C shim (header types visible via the existing include).
- Union-typed and union-containing struct-by-value parameters remain SKIP.

## M4c — tagged-union ADT bridging (declarative tag association)

- New `[[unions]]` bindgen.toml rules declare the host struct's `tagField`/`payloadField`,
  the `tagEnum` providing discriminant constants, and per-variant `tag` → `member` mapping.
  Associations must be declared; they are never inferred from usage.
- Generation produces an Eidos ADT (`EventValue :: type { KindClick :: type(Int32), ... }`),
  `event_value_decode :: RawPtr -> EventValue` (reads the tag, branches, loads the member;
  unknown tags fall back to the last variant), and `event_value_encode` (writes tag + member),
  backed by struct-field shim helpers (tag get/set with `int64_t` widening, payload
  address-of). Variant members must map to scalars or pointers.
- Verified end to end: generated modules pass the full semantic pipeline, shims compile under
  clang, and a native smoke round-trips encode → decode → pattern match through a C-side
  tagged-union struct.
