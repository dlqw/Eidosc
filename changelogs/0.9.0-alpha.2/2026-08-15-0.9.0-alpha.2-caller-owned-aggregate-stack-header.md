# Give caller-owned aggregate blobs a stack EidosHeader

- The caller-owned out-return ABI wrote returned aggregates into a raw stack blob
  in the caller's frame with no `EidosHeader`. Any refcount-protocol callee that
  received the blob — `ref`-receiver accessors such as
  `Network.bytes_content_type` start with `eidos_incref_local` — treated the 8
  bytes before the blob as a reference count and incremented them. When the
  compiler placed a live spill slot there, the increment landed inside a live
  pointer (a +1 on its low word) and the program crashed natively at optimized
  levels — the std.Network smoke test's 0xC0000409/0xC0000005 (issue #82).
- The blob allocation now wraps the aggregate as
  `{ [2 x i32] header, aggregate, inline array storages... }`, the destination
  pointer is the aggregate field (field 1), and the entry block initializes the
  header with `EIDOS_STACK_BIT | 1` plus the constructor's runtime type id — the
  same convention `eidos_array_new_in_storage` already uses for inline arrays.
  incref/decref on the blob now bump a well-formed stack header that never
  frees, and `eidos_type_id` reports the real constructor type.
- Array-storage GEPs into the wrapper shift by one field accordingly.
- Regression: `CallerOwnedAggregateBlob_CarriesStackHeader_RefReceiverAccessorsAreSafe`
  asserts the emitted IR carries the header stores, and the previously crashing
  `StdNetworkLocalSuccessAndRedirect_NativeRuntimeSmoke_WhenToolchainAvailable`
  now passes (exit 0, all 31 checks).
