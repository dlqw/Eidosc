# Render diagnostics against the file each label points to

- `DiagnosticRenderer` printed every label at the root input file's path and
  excerpted every label from the root input's source text, even when the label's
  span carried a different `FilePath`. Borrow-check diagnostics raised inside
  imported modules (for example the `projects/ecc` template) therefore rendered
  as `main.eidos:<line>` with an empty or unrelated excerpt, hiding the actual
  offending module file (issue #83).
- Labels whose span names a different file now print that file's path and
  excerpt its text. The text is resolved through the new
  `DiagnosticRenderOptions.SourceResolver` hook when provided, with a guarded
  on-disk read as fallback for absolute paths; when neither resolves (virtual
  source names such as `<precompiled:...>`), the label still reports its own
  path plus a `(source text unavailable)` note instead of a wrong excerpt from
  the root file.
- Labels without a file path keep rendering against the root source exactly as
  before; unit tests cover the resolved-foreign, unresolved-foreign and
  root-file label paths.
