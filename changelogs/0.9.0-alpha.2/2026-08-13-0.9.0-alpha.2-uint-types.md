# Unsigned integer builtin types reach the backend boundary

- Add `UInt64`/`UInt32`/`UInt16`/`UInt8` builtin scalar types (type IDs, `BaseTypes`, symbol-table registration, and display names).
- Lower unsigned scalars to the LLVM integer types (`i64`/`i32`/`i16`/`i8`) and accept them at the MIR/backend boundary, mirroring the narrow signed scalars.
- Mark the unsigned scalars FFI-safe and give them C ABI size/alignment, so `@[extern(c)]` declarations and `@[repr(c)]` struct fields of unsigned type parse and lower.
- Adds regression coverage (`MirValidatorTests`) for the four unsigned builtins.

Known follow-up (recorded in the toolchain plan, section 7): constructing an unsigned value in Eidos source still needs suffix literals (e.g. `5u32`) and explicit `UInt*`/`Int` conversion functions, which are a separate language-surface change. This change only establishes the type and backend boundary.
