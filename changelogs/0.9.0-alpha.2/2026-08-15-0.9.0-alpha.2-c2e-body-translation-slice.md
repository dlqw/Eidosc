# C2E vertical slice: translating C function bodies to Eidos

First milestone of the body-translation (C2E) toolchain over the shared libclang frontend:

- New `CBodyTranslator` (clang cursor kinds verified empirically against clang 22: statements
  202/205/207/209/214/231, expressions 100/101/103/106/107/114) translates C function bodies
  source-to-source into Eidos: scalar `int`/`float` arithmetic and comparisons, local variable
  declarations and assignments (`mut` locals, `:=` assignments), `if`/`else` (Unit-armed
  selection statements), `while`/`for` (desugared to `loop` + guarded `break`), `return`,
  integer/floating literals (via `clang_Cursor_Evaluate`), and calls to functions translated
  from the same file. Unsupported constructs skip the function with a recorded reason.
- C fixed-width integer overflow is not modeled in the slice: all C integers widen to Eidos
  `Int` (arithmetic/compare semantics coincide for in-range values; documented limitation).
- Parity gate: the same C source compiled by clang and translated-then-compiled by Eidos runs
  with identical exit codes (while/for/if-else/cross-function-call composition), natively.
- This lands the M7 slice of the 0.9.0 closing triad; the feature matrix (pointers via
  RawPtr, unions via the M4 bridge, extern interop, switch/goto, varargs) extends the
  translator next.
