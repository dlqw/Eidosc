# Capturing closures as ctx-pointer C callbacks

- New `std.Ffi` intrinsics `cfn_ctx_from` / `cfn_ctx_data` (overloads 0..6 callback arguments)
  serve C APIs following the ctx-pointer convention `callback(void* ctx, args...)`:
  the closure's invoke thunk has ABI `(closure_ptr, args...)` — isomorphic to the C callback
  with the closure pointer as ctx — so `Ffi.cfn_ctx_from(closure)` yields the callback
  function pointer (loading `invoke_fn` at closure offset 8) and `Ffi.cfn_ctx_data(closure)`
  yields the closure object pointer to pass as ctx. The Cfn result type prepends the ctx slot
  (`Cfn[RawPtr, A..., R]`).
- Zero-capture functions passed to `cfn_ctx_from` report `E3053` with guidance to wrap in a
  lambda; plain `Ffi.cfn_from` keeps its zero-capture semantics, its error message now points
  at `cfn_ctx_from`, and the dead invoke_fn emission after that diagnostic is removed.
- Closure lifetime remains the caller's responsibility for the duration of any C-side
  registration (documented on the intrinsics). libffi-style trampolines for ctx-less
  callbacks remain explicitly out of scope.
- Verified natively: a C visitor `int (*)(void*, int)` driven over a static array invokes an
  Eidos closure capturing an `Int32` base; the captured value participates in every callback.
