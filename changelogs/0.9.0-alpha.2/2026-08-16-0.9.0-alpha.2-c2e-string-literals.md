# C2E: string literals cross the boundary via Ffi.to_c_string

Clears the 101-site string-literal blocker (handover §3-#3). C string
literals now translate instead of skipping:

- `TranslateStringLiteral` decodes the clang spelling (including `\xNN` and
  value-re-encoded forms; unknown escapes read as literal backslash+char,
  matching clang's value-based spelling of warned-invalid C escapes) and
  re-encodes into the Eidos escape set; control characters without an
  Eidos escape fail loudly with a dedicated skip reason.
- A string literal flowing into a RawPtr context — `const char*` locals,
  returns, assignments, and call arguments (external and internal) — is
  wrapped as `Ffi.to_c_string(<literal>)` at the boundary. The literal may
  arrive wrapped in UnexposedExpr (implicit `char[N] -> const char*`
  decay), so the check unwraps wrapper chains first.
- Literals consumed inside translated code keep Eidos `String` type; the
  pointer conversion happens only where the C ABI demands it.

Parity gate `C2E_StringLiterals_ParityWithClang` covers a local, a direct
argument, a returned literal, and escape handling (exit 22 == clang).
