# Language: bitwise operators `& | ^ << >>` (Int-only)

Implements Plan A of the C2E floor-thinning handover §4.1 — the only
language-level hard gap that blocked 93 raylib functions from translation.

- Tokens: `^`, `<<`, `>>` join the lexer (maximal munch alongside `>>=`,
  `>>>`, `<<<`); `|` (OpPipe) and `&` (OpPatternAnd) were already lexed but
  unused by the expression grammar, so they now read as bitwise operators in
  expression position. Patterns, ADT separators, and list-comprehension
  qualifiers keep their existing `|`/`&` meanings.
- Precedence mirrors C exactly, inserted between the existing levels:
  `<<`/`>>` above comparison, then `&` > `^` > `|` between comparison and
  `&&` (levels renumbered; all references go through the `Precedence`
  constants).
- Ambiguity fixes for the two expression contexts where `|` was already a
  separator: `ParseExpr` gains a `stopAtBitBar` mode that stops the binary
  spine at `|` (propagated through operand recursion, reset by any fresh
  nested context such as parens). List-comprehension outputs
  (`[e | quals]`) and decision-table key lists (`| k1 | k2`) parse with it;
  a top-level bitwise-or in those positions now needs parentheses.
- Typing: `Int -> Int -> Int` only (`InferBitwiseBinary` unifies both sides
  with Int; new diagnostic `BitwiseOperandMustBeInt`). No Num/Eq/Ord trait
  constraints are generated. Comptime folding and the interpreter evaluate
  the five operators (interpreter `>>` is arithmetic shift, matching i64).
- HIR/MIR gain `BitAnd BitOr BitXor Shl Shr`; LLVM emits `and or xor shl`
  and `ashr`/`lshr` by operand signedness (same `isUnsigned` test as
  `sdiv`/`udiv`), coercing operands to the i64 word.
- C2E: C `& | ^ << >>` translate to the same-shaped Eidos operators, and
  unary `~x` desugars to `(x ^ -1)`; the translator re-emits C's implicit
  precedence as flat text, which the matching Eidos precedence regroups
  identically (covered by the parity test).
- Parity gate `C2E_BitwiseOperators_ParityWithClang`: clang-compiled C vs
  translated+compiled Eidos agree on all five operators plus `~`, including
  a precedence-sensitive expression.

Verification: full C2E suite 8/8; raylib probe translation counts rise with
zero regressions (rcore 638→661, rtext 319→323, rtextures 464→489, raymath
159→162); raylib-c2e regeneration byte-identical; clean snake-gui-c2e
rebuild reproduces checksum anchor 837999808 and the GUI smoke survives.
