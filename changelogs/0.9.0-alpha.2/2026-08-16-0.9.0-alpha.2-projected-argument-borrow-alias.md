# Restore copy-aware borrow aliases for projected call arguments

- `ShouldCreateBorrowAliasForProjectedArgument` had been changed to always return false,
  so loading a projected argument (for example `texts[idx]`) always materialized an
  independently owned value. For non-Copy element types that silently moved storage out
  of the owning aggregate, and the borrow checker could no longer see the alias.
- The helper is copy-aware again: Copy element types load as independent copies, while
  non-Copy projected loads create borrow aliases so capturing them in a partial
  application reports E1002 (`BorrowArgumentRequiresOwnershipButAlias`) as designed.
- `generic_nonzero_partial_dynamic_index_noncopy_error.eidos` reports E1002 again and
  all 68 CoreFixtureRegression tests pass, including the copy-element success fixtures.
