# C2E: array subscript, local array buffers, and width-typed pointer access

Clears the largest L2 blocker class (handover §3-#1/#2) and fixes a latent
width bug in existing pointer dereference. `a[i]` now translates instead of
skipping:

- Element address is `Ffi.offset_bytes(base)(index * sizeof(T))` with the
  size taken from clang's layout facts (`clang_Type_getSizeOf`); nested
  subscripts (`rows[i][j]`) compose because the inner element's rvalue is a
  pointer load.
- Read, write (`a[i] = v`), compound assignment (`a[i] += v`), and statement
  increment (`a[i]++`) all round-trip through the same address expression;
  `&a[i]` returns the address itself.
- `T a[N]` locals map to RawPtr heap buffers: `Ffi.malloc(N * sizeof(T))`
  without an initializer, `Ffi.calloc` + per-element stores with a brace
  initializer (C zero-fill semantics). Record/nested-array elements are
  buffer-only (member access via the subscript accessor bridge);
  `char a[N] = "..."` skips with a reason.
- `p[i].f` member access on record-element subscripts goes through the
  `c2e_<Record>_<member>_get/set` accessor bridge on the computed address.
- `sizeof(x)`/`sizeof(T)` evaluates to a constant (clang constant evaluation
  first, operand-type layout size as fallback). New libclang export:
  `clang_getArrayElementType`.

## Width-typed pointer access (correctness fix)

`Ffi.load[Int]`/`store[Int]` are i64 accesses, but C `int` is 4 bytes: the
existing `*p` dereference of `int*` silently loaded/stored 8 bytes (the
pointer parity gate passed only because its fixture used `long long`).
Same class of bug for C `float` (32-bit) vs Eidos `Float` (f64). Fixed by
introducing typed accessors and selecting them by element layout width:

- std.Ffi gains internal intrinsics `ptr_load_i16`/`ptr_store_i16` (zext/trunc)
  and `ptr_load_f32`/`ptr_store_f32` (fpext/fptrunc), and exported wrappers
  `load_i32/store_i32`, `load_i16/store_i16`, `load_i8/store_i8`,
  `load_f32/store_f32`. The codegen dispatch tables and MirToLlvmConverter
  gain the i16/f32 entries plus fpext/fptrunc conversion branches.
- CBodyTranslator picks the variant by clang element kind and byte size
  (8→`[Int]`, 4→`_i32`, 2→`_i16`, 1→`_i8`, float→`_f32`, double→`[Float]`,
  pointer→`[RawPtr]`) for subscripts, dereferences (`*p`, `*p = v`), and
  local-array initializer stores.

Record member accessors over C `float` members previously returned `float`
across the extern(c) ABI while the Eidos declaration promised `Float` (f64);
the generated accessor shims now use double signatures with explicit C-side
narrowing.

## Generated-code correctness fixes found by the new parity gate

- The `for` desugar hoists `mut i := 0;` into the enclosing scope, so two
  loops declaring `int i` in one function produced E3000 duplicate bindings.
  The whole desugar is now wrapped in a bare block statement (C `for` has its
  own scope); the loop's closing brace carries a `;` so a following `()`
  statement is not parsed as application (E4000).
- Effect authorization does not infer `need ffi` for calls in loop bodies or
  nested operand positions (tail/statement positions are inferred). C2E now
  tracks Ffi/extern/accessor usage per function (Mark counters + dictionary
  growth snapshots) and propagates it along the internal call graph to a
  fixpoint, emitting `need ffi` on exactly the affected signatures.
- Statement-position `a[i]++` was detected via the *first* punctuation token
  (`[`), so postfix increment on subscripts never matched; detection now
  scans for an `++`/`--` token anywhere in the operator extent. `sizeof`
  appears as cursor kind 136 (UnaryExpr) in this libclang, not 112
  (UnaryOperator); both route through the unary translator.

Parity gate `C2E_ArraySubscript_ParityWithClang` covers int/float/double
element arrays, f32 scaling, double-indirect rows, record-element member
read/write, local arrays with and without initializers, `&a[i]` plus
deref, and `sizeof` (exit code == clang-compiled reference).
