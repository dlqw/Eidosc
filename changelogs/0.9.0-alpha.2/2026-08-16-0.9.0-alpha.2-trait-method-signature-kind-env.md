# Register owner trait type parameters when rebuilding constrained method signatures

- `TryCreateConstrainedTraitMethodType` rebuilt a trait method's signature with only the
  method's own type parameters registered, so kind2 parameters owned by the trait (`F` in
  `Applicative[F: kind2]`) fell through to symbol resolution and were arity-checked as
  nullary types: `Type 'F' expects 0 type argument(s), but got 1` on `Applicative.apply`
  and `Traversable.traverse`.
- The rebuild now resolves the owner trait via `FuncSymbol.OwnerTrait` and registers its
  type parameters (and kind bindings) alongside the method's own, matching
  `InferFunctionSignatureType`'s outer/inner handling.
- Fixes the `analyze`/query and full-build failures on `std/traversable.eidos` (issue #75);
  `Compile_SequentialPhysicalStdlibDocuments_HasNoErrors` and
  `Compile_TypesQueryWithPrecompiledStd_UsesSignatureOnlyImportedBodies` pass again.
