# In-process libclang extractor layer for `pkg bind`

- Add the first milestone of the clang-driven C→Eidos binding toolchain (P0 of `docs/plans/tooling/eidos-clang-c-transpiler-plan-2026-08-13.zh-CN.md`): an in-process libclang P/Invoke layer (`Eidosc.Bindgen.Clang`) with platform-aware library discovery aligned to the existing clang tool search.
- Add a full declaration extractor (`ClangHeaderParser`) producing `CHeaderIr` with include expansion, layout facts, unions, typedef chains, enum values, macro constants, function pointers with arity, variadic/inline flags, and globals.
- `pkg bind` gains `parseMode = "clang"` (with `clangDefines`/`clangArgs`/`[options]`); the regex `SimpleCHeaderParser` remains the `"simple"` fallback.
- Auto shims now cover struct-by-value parameters (`void*`), struct-by-value returns (static-slot pointer shim), and narrowing of non-64-bit scalars (`int64_t`/`double` shims with C casts).
- The raylib gate (real `raylib.h`, clang mode) generates 599 bindings, 6 legitimate SKIPs, and a 2400-line auto shim that replaces the hand-written `eidos_raylib.c`; the generated module passes the full semantic pipeline.
- Known compiler gap (recorded in the plan, §7.2): the MIR/backend boundary only supports 64-bit scalars — `Int32`/`Int16`/`Int8`/`Float32` as extern parameters/returns hit `E5337`; the toolchain works around it with narrowing shims, and Eidosc support for narrow FFI scalars is a separate compiler work item.

The C→Eidos toolchain is the Eidos `0.9.0` closing feature: `0.9.0` stable will not release until the full toolchain (declaration migration, mixed compilation, body translation) lands.

This feature targets Eidos `0.9.0-alpha.2`; the latest immutable release is `0.9.0-alpha.1`.
