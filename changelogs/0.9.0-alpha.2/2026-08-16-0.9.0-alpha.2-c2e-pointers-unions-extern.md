# C2E feature matrix: pointers, record member bridge, external calls

- The C-to-Eidos body translator now maps C `T*` (and `void*`/multi-level pointers) to
  `RawPtr`: `*p` reads and `*p = v` writes lower to `Ffi.load[T]`/`Ffi.store[T]`,
  `p == 0` / `p != 0` / `!p` lower to `Ffi.pointer_eq(...)`, and 0 / `(T*)0` in pointer
  positions lower to `Ffi.null_pointer()` (non-null integers used as pointers are
  rejected with a skip reason).
- `union`/`struct` pointer member access (`s->field` reads and writes) goes through an
  M4-style accessor bridge: the translator emits `c2e_<Record>_<field>_get/set`
  `extern(c)` declarations plus a companion C shim source (`C2EResult.NativeShimSource`)
  that includes the original C file and defines the accessors for native linking.
- Calls to functions declared but not defined in the translated file (library-internal
  or cross-TU prototypes) now translate to `c2e_ext_<name>` calls backed by generated
  `extern(c)` declarations derived from the prototype's parameter and return types
  (variadic prototypes are still skipped).
- Unary `-` on scalars and bare call statements are now supported; unary operator kinds
  were re-probed against clang 22 (`UnaryOperator` is 112, not 115) and `MemberRefExpr`
  (102) / `CStyleCastExpr` (117) were added to the statement/expression kind table.
- Adds clang-parity native gates: `C2E_PointerDerefAndNull_ParityWithClang`,
  `C2E_UnionMemberBridge_ParityWithClang`, `C2E_ExternalCall_ParityWithClang`.
