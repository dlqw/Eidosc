# extern(c) global variables

- Module-level `mut` bindings accept a declaration form without an initializer:
  `@[extern(c, name: "symbol")] mut state : Int;` lowers to a declaration-only LLVM global
  (`@symbol = external global i64`) bound to the exact C symbol, with loads and stores going
  through the ordinary module-variable machinery.
- The `extern` clause schema now targets value declarations as well as functions; foreign
  variables must be mutable, carry an explicit type annotation, and cannot have an initializer
  (`E3050`). A plain `mut` binding without an initializer and without `extern` is rejected
  (`E3050`); foreign variables do not require `need ffi` because value bindings carry no
  effect row.
- extern variable metadata flows `VarSymbol` → `HirVarDecl` → `MirModuleVar` (`IsExternal`/
  `ExternalName`) and survives HIR/MIR state payload round-trips.
- `pkg bind` replaces the "Eidos has no module-level mutable state" global SKIP with extern(c)
  declarations for scalar- and pointer-typed C globals (`Int32`/`Float32`/`RawPtr` and
  friends); aggregate- and enum-typed globals remain SKIP comments pending shim accessors.
- Native tests link a C global via the new `nativeCSource` helper: reads, writes, and
  persistence across calls verified end to end.
- Known limitation (unchanged): assigning to a module variable imported from another module
  still parses as a fresh local binding; cross-module reads via qualified paths work.
