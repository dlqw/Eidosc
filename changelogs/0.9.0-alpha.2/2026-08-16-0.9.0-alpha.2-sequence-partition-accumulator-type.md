# Fix sequence partition accumulators and queued slot-store ordering

- Direct partition lowering typed its `left`/`right` accumulator locals with the partition
  *result* type — the `(sequence, sequence)` tuple — instead of the tuple's field type, so
  the array-pointer results of `array_new`/`array_push` were bridged into tuple-typed
  slots by loading a bogus `{ptr, ptr}` header (refcount+length bits) and pushing through
  it, corrupting the heap at runtime.
- `TryGetPartitionElementType` now returns the tuple field type and the plan uses it for
  the accumulators and the aggregate field stores; `SeqPartition_WithTupleResult_NativeSmoke_ReturnsPartitionSizes`
  runs natively again.
- `QueueStoreToLocalSlot` queued only the store while appending its struct-value load
  directly to the current block, so the load could precede the producing instruction
  (an "Instruction does not dominate all uses" verifier failure on the emitted IR); the
  load is now queued with the store after the producing instruction.
