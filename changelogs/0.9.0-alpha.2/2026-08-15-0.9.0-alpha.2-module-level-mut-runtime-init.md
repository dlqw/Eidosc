# Runtime initialization for module-level mutable globals

- Module-level `mut` initializers are no longer restricted to statically lowerable int/float
  scalars: calls, aggregates, string literals, and other runtime values initialize through a
  synthesized per-variable init function (`__module_var_init_<name>`) invoked from
  `eidos_module_init` before `eidos_main`, storing into the zero-initialized global.
- Runtime initializers are ordered by dependency (a var whose initializer reads another module
  var initializes after it); cycles among module vars report `E5300` and leave the members
  zero-initialized. `E5312` now fires only for initializers that cannot serve as init-function
  bodies (control-flow escape: return/break/loop/comprehension); `E5313` remains the fallback
  when no static or runtime path resolves (for example in partial recompilation units, which
  still zero-initialize without emitting module init).
- Module-variable globals now use `internal` linkage, removing them from the external symbol
  surface.
- String-literal module `mut` initializers compile successfully end to end (previously `E5313`
  with a zero fallback); `eidos_module_init` is emitted whenever runtime-initialized module
  vars exist, not only for ADT destructor registration.
