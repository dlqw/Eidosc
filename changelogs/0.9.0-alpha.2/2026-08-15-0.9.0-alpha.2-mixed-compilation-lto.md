# True cross-language LTO for mixed compilation

- Under `--lto`, the Eidos IR compile step now routes through `clang -x ir -c -flto`
  (LLVM bitcode objects) instead of `llc -filetype=obj` (native objects): previously the
  linker's `-flto` had nothing to optimize since every input was a native object.
- `GetDefaultClangObjectCompileFlags` appends `-flto` when LTO is enabled, which uniformly
  covers native FFI sources, the entry shim, and runtime compilation — and flows into their
  object cache keys and backend configuration hashes automatically.
- Linking keeps `-flto` (+ lld on Windows). Mixed Eidos/C builds now expose cross-language
  inlining at the link step; verified natively that an Eidos→C extern call round-trips with
  identical behavior with LTO on and off.
