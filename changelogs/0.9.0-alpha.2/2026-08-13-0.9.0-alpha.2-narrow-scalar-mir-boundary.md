# Narrow builtin scalars reach the MIR/backend boundary

- Fix `E5337` (`Unknown MIR TypeId`): the `MirValidator.IsBuiltinLoweringType` whitelist now accepts `Int64`/`Int32`/`Int16`/`Int8` and `Float64`/`Float32`/`Float16`, matching the LLVM lowering already present in `TypeLowering` (`i64`/`i32`/`i16`/`i8`/`double`/`float`/`half`).
- `@[extern(c)]` declarations and `@[repr(c)]` struct fields of narrow scalar type now pass MIR validation and lower through the existing cstruct byte-offset accessors.
- Adds regression coverage (`MirValidatorTests`) asserting the seven narrow builtin scalars are accepted at the backend boundary.

Known follow-up (recorded in the toolchain plan, section 7.2): constructing a narrow value in Eidos source (e.g. passing `5` to an `Int32` parameter) still reports a type mismatch, because Eidos has no implicit numeric narrowing and no narrow literal/conversion surface. Narrow value construction is a separate language/stdlib work item; this change only fixes the backend boundary.
