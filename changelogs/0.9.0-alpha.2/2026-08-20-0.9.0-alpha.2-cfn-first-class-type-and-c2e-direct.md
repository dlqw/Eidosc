# Cfn first-class type positions and C2E direct function-pointer translation

- `Cfn[A..., R]` now participates in kind inference as a complete type in type aliases, ADT fields, `@[repr(c)]` fields, generic containers, nested `Cfn` signatures, and module-level mutable bindings. Zero-parameter `Cfn[R]` and arbitrary arity are accepted everywhere the compiler intrinsic already supported them.
- `@[repr(c)]` fields declared as `Cfn[A..., R]` keep their full type through generated getter/setter accessors (C ABI remains a pointer).
- `std.Ffi` public `cfn_from`/`cfn_call`/`cfn_ctx_*` declaration anchors extended from 0..6 to 0..12 parameters; the compiler intrinsic resolver continues to accept any arity. BindGen callback mapping no longer rejects zero- or high-arity function pointers.
- C2E now translates typed C function pointers directly to `Cfn`: declarations/typedefs/parameters/returns/record fields/array elements use `Cfn[...]`, function-name decay and `&fn` become `Ffi.cfn_from`, indirect calls become `Ffi.cfn_call`, and null/equality use `Ffi.is_null`/`Ffi.pointer_eq`. The `c2e_icall_{digest}`/`c2e_addr_*` digest shims remain only as a fallback for untyped pointers and C symbols without an Eidos binding.
- New clang parity gate `C2E_FunctionPointers_ParityWithClang` covers local/global/record-field function pointers, arrays, null sentinels, pointer equality, reassignment, and function-pointer returns.
- Targeting `0.9.0-alpha.2`; part of the C2E function-pointer two-way migration (§11.5 of the C/Eidos differences plan).
