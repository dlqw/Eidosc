# Sequence predicate ownership and single-pass algorithms

- Classification: fix
- Latest authoritative Std version: `0.2.0-alpha.1`
- Target Std version: `0.2.0-alpha.2`

## Changed

- Changed `Seq.filter`, `Seq.find`, and `Seq.partition` to accept shared-borrow predicates (`Ref[T] -> Bool`), so they can retain or route move-only elements without implicit cloning.
- Reimplemented `Seq.find` as a short-circuiting scan without materializing a filtered sequence.
- Reimplemented `Seq.partition` as one ordered pass that invokes its predicate exactly once per element.
- Reimplemented `Seq.drop` and `Seq.reverse` as linear index loops with compiler-selected result capacity instead of recursive tail/append chains.
- Updated `AsyncExtra.partition` to preserve the canonical borrowed predicate contract.

## Compatibility

- This intentionally removes the owned `T -> Bool` predicate contract from the three retaining operations. Eidos ownership contracts are signature-derived, so the compiler cannot silently reinterpret an owned predicate as a borrow or insert `Clone`.
- Consuming terminals such as `Seq.any`, `Seq.all`, `Seq.count`, and `Seq.find_index` keep their existing owned predicate contracts.
