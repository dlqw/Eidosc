# Native ownership lowering and automatic reuse

- Classification: feature
- Latest immutable Eidosc release: `0.4.0-alpha.3`
- Target Eidosc version: `0.5.0-alpha.1`

## Added

- Enabled native drop insertion across overwrite, branch, loop, tail-call, partial-move, intrinsic, FFI, and external-declaration paths, with path-sensitive ownership transfer and balanced destruction.
- Added scalar-tag lowering for closed payloadless ADTs and inline value ABI lowering for small `Copy` records, including cache serialization and cross-function calls.
- Added compiler-owned destructive projection moves, copy/drop elision, record-update fusion, and unique-owner reuse preparation.
- Added consuming runtime-array primitives and fusion paths for slicing, prefix take, prepend, append, self-extension, and right-buffer growth.
- Added stable unique-argument function variants so cross-function record updates can directly mutate compiler-proven single-owner payloads while general callers retain copy-on-write fallback behavior.
- Added conditional sequence-window fusion that recognizes natural `take(length - 1)` and nested prepend expressions and lowers them to one capacity check and one backing-buffer move.
- Added compiler-internal read-only range variants for sequence consumers, allowing natural slice-and-search expressions to avoid materializing a temporary container without exposing another user-facing sequence abstraction.
- Added a consuming tail-window update primitive that combines tail removal, prefix insertion, managed-element release, and copy-on-write fallback in one backing-buffer move.
- Added compiler-proven unique sequence update variants with statically selected managed-element policy and a fixed-width 16-byte aggregate path, so hot loops avoid repeated ownership-policy and element-width dispatch.
- Added runtime record retainer registration so copy-on-write updates preserve managed fields when a shared record must be cloned.

## Changed

- Record updates and sequence construction now reuse uniquely owned storage when legal and preserve copy-on-write semantics when aliases exist.
- Read-only nested sequence projections no longer create transient managed owners solely to access an element.
- Read-only range traversal now preserves the original borrow directly instead of creating per-element sequence owners, keeping uniquely owned storage available for the following consuming update.
- Read-only range traversal lowers proven length/index operations directly to header loads and typed pointer arithmetic; concrete element width is folded into the generated loop instead of loaded on every iteration.
- Native LLVM lowering statically resolves runtime type IDs for exact single-constructor nominal types, keeps aggregate move sources initialized for later cleanup, and marks specialization variants plus their immediate ABI bridge callers `alwaysinline` while retaining externally linkable caller symbols.
- Windows LTO links through LLVM `lld`, matching the selected native optimization pipeline.

## Correctness

- MIR liveness and drop placement now distinguish upward-exposed uses, borrow aliases, consuming calls, and bodyless declarations.
- Incremental MIR payloads and fingerprints preserve constructor layout, scalar representation, `Copy` evidence, and record-update metadata.
- Added native allocation-balance, runtime copy-on-write, branch/loop, stack-promotion, ASAN, and long-running Snake regression coverage.
- Added opt-in runtime allocation/reuse reporting and a three-language Snake gate that checks a shared checksum, interleaved Rust/Zig/Eidos timings, and zero steady-state allocation growth after capacity warmup.
