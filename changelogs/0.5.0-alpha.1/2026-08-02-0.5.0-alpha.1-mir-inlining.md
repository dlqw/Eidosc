# Register sound MIR inlining

- Classification: feature
- Latest immutable Eidosc release: `0.4.0-alpha.3`
- Target Eidosc version: `0.5.0-alpha.1`

## Added

- Registered MIR `Inlining` in the default optimizer after trusted function summaries are available and before ownership finalization.
- Inlines only small, non-recursive, exact single-entry/single-return bodies whose summaries explicitly permit body inlining.

## Correctness contract

- Requires exact argument count, return shape, and parameter/return types, limits active inlining to primitive and structurally proven copy-like locals/results, and rejects borrowed call arguments, Unit call-sugar boundaries, generic or runtime-word ABI functions, caller-owned aggregate ABI functions, intrinsics, constructors, trait dispatch, closure bodies, and unsafe ownership boundaries.
- Remaps every callee local and temporary, including projected/index operands and return values, and emits ownership-aware move/load bindings at parameter and return boundaries.
- Resolves candidates by structured symbol/function identity first, rejects ambiguous name fallback, and preserves all caller and module metadata through the transform.

## Verification

- Added focused MIR shape tests for local/temp collision avoidance, projected moves, Unit and borrowed arguments, generic/trait/constructor/closure boundaries, metadata preservation, and default-pipeline registration.
- Added native managed-record ownership coverage to ensure inlining does not introduce leaks, double releases, or invalid stack promotion.
