# Eidosc 0.5.0-alpha.1 systemic Prelude, overload, and visibility changes

- Fixed all IDE/LSP absolute-source offsets through one UTF-16 coordinate map, including multiline diagnostics, suggestions, rename, document symbols, import insertion, zero-length insertion, deletion, document-versioned edits, and applied-edit recompilation.
- Made module visibility strictly `export`-based and prevented `compiler(internal)` and raw intrinsic symbols from leaking through same-package imports, completion, or global precompiled fallbacks.
- Split the automatically opened Prelude Core Image from the explicit `std` package graph and replaced `noImplicitStdlib` with `noImplicitPrelude`.
- Opened Prelude in every non-Core module, including imported `std` and nested user modules, and preserved the same Core Image owner identity and `SymbolId` through Types, HIR, MIR, cache payloads, and direct Core Image compilation.
- Delayed overload ambiguity until the complete curried application spine is known and ranks specificity across every applied argument.
- Added general implicit shared borrowing for `Ref[T]` call parameters, ranked below exact by-value matches, and saturation preference for overloads versus partial applications.
- Added compiler semantic roles on exact toolchain-owned function declarations and migrated `do`, coalescing, composition, prepend/append-last, fmap, apply, bind, and append elaboration away from hard-coded standard-library paths.
- Unknown roles report `E3058`; missing or duplicate required roles report deterministic `E5208` diagnostics.
- Removed legacy type-suffixed output builtins and migration recognition; runtime output now crosses only structured compiler-internal `write_*_raw` intrinsics.
