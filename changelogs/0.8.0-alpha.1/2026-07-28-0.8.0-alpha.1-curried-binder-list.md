# Curried binder lists

- Sync ID: `eidos-2026-07-28-curried-binder-list`
- Classification: feature
- Latest immutable Eidosc release: `0.4.0-alpha.3`
- Target Eidosc version: `0.8.0-alpha.1`

## Added

- Added unparenthesized curried binder lists such as `left, right => left + right` to function branches and braced lambdas.
- Kept parenthesized `(left, right) => ...` unambiguously unary over a tuple, including tuple destructuring and tuple-valued pattern matching.
- Added guards over a complete binder list and preserved staged-guard chains when flattening would change semantics.

## Changed

- The formatter canonicalizes simple `left => right => body` chains to `left, right => body` and keeps binder commas inside one branch rather than treating them as branch delimiters.
- Bindgen and the bundled standard library now emit curried binder lists for multi-argument curried functions.
- Lambda inference and callable-shape selection treat binder lists as nested unary function types, preserving partial application, saturated application, effects, and the existing runtime ABI.

## Migration

- A former `(left, right) => body` branch used as shorthand for two curried arguments must become `left, right => body`.
- A real tuple parameter remains `(left, right) => body`.
- Two curried tuple parameters use `(left_a, left_b), (right_a, right_b) => body`.
