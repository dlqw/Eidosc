# Borrow diagnostics regression fixes

- Classification: fix
- Latest immutable Eidosc release: `0.4.0-alpha.3`
- Target Eidosc version: `0.8.0-alpha.1`

## Fixed

- Specializations of value-returning generics no longer inherit a call-site
  borrow view (`Ref`/`MutRef`) as their return type; a borrow view adjacent to
  the call is an ABI artifact, not the function result type. This removes the
  false `E1004` "returned borrow must come from an input parameter" reports on
  stdlib consumers such as `AsyncExtra.for_each_thunk`.
- Projected loads cloned during generic specialization recompute their borrow
  alias flag from the substituted element type, so Copy-element indexed reads
  inside specialized functions no longer create spurious borrow aliases. This
  removes the false `E1002` ownership-alias reports on `Seq.EqSeqT.eq`.
- Dead code elimination no longer removes borrow-creating loads
  (`load_mut`/borrow-alias loads) whose target local is unused; borrow creation
  has observable borrow-checker semantics, and dropping it silently suppressed
  borrow-conflict diagnostics.
- The call-target type refinement in the generic specializer no longer
  overwrites a concrete value type with an adjacent borrow view type.
- Trait constraint resolution and trait dispatch now fall back from an exact
  closed-case type (for example `Point:: type(Int)`) to its root ADT type when
  looking up instances, and impls declared on a root ADT are indexed under its
  case types as well; user trait instances on sealed-sum ADTs resolve for
  values carrying the case identity.

## Correctness

- Updated fixture expectations for `generic_nonzero_partial_*` error cases
  whose second diagnostic no longer applies after the curried binder-list
  migration, and for `Ordering.compare_desc` LLVM ABI assertions after scalar
  tag lowering (`i32` return instead of `ptr`).
