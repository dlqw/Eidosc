# Compiler-managed unique sequence construction

- Classification: perf
- Latest immutable Eidosc release: `0.5.0-alpha.1`
- Target Eidosc version: `0.5.0-alpha.2`
- Eidos language classification: none

## Changed

- Added a unified RuntimeArray build lowering for capacity planning and compiler-generated `array_new`, `array_length`, and `array_push` operations.
- Added proof-driven `map` -> `filter` -> `collect` fusion with one source traversal and one result collector while retaining eager fallback when callback, ownership, or shape proofs fail.
- Added local RuntimeArray storage promotion for constant-capacity, uniquely owned, non-escaping arrays up to 4096 bytes.
- Lowered promoted arrays through `eidos_array_new_in_storage`, retaining automatic heap growth and live-pointer length reads after growth.
- Added MIR fingerprint and v14 payload coverage for local array storage metadata.
- Kept ordinary `Seq` source as the performance path: no capacity constants, specialized containers, optimizer annotations, or `SeqBuilder` rewrite are required.

## Measured

For `Seq.filter(Seq.map([1, 2, 3, 4])(increment))(predicate)` followed by `Seq.len`:

- `origin/main@5cbf0cd`: 7 runtime heap allocations;
- collect fusion without local storage promotion: 2 allocations;
- collect fusion with local storage promotion: 0 allocations;
- pipeline traversals: 2 -> 1;
- eager intermediate sequences: 1 -> 0;
- RuntimeArray values constructed by the complete expression: 3 -> 2, with both remaining arrays backed by local storage;
- native checksum/length: 3 in every configuration.

A 10-iteration, 2-warmup `profile-batch` run to MIR measured 1628.04 ms at the baseline and 1647.10 ms with the complete optimization (+1.17%). The sequence fusion and storage promotion pass bodies accounted for about 0.25 ms combined in the optimized profile.

## Verification

- Added capacity overflow, proof fallback, metadata fingerprint/roundtrip, LLVM storage/growth, MIR shape/profile, and native allocation-counter coverage.
