# Eidos 0.9.0-alpha.1

## Single Eidos release version

- Unifies the Eidos language, Eidosc, Std, Eidosup, Bindgen, official editor plugins, and the Clang Extractor under one user-visible Eidos version and coordinated release train.
- Adds `eng/Eidos.Version.props` as the only hand-maintained version input in the Eidosc repository; component props derive their build and package identities from it.
- Preserves independent schema, protocol, cache-format, channel, and Git identities as internal diagnostics rather than user-facing product versions.
- Requires unchanged components to be republished with the train. A proof-driven fast lane may skip full functional tests only when the complete artifact source set is unchanged; version, package, checksum, and install-smoke gates remain mandatory.
- Retires the independent Std version and release identity. Eidosup and Bindgen keep namespaced artifact/tag identities but use the same Eidos version.

## Functional language and compiler work

- Includes the accumulated 0.7/0.8 compiler work and the 0.9 obligation/evidence solver with principled `do` Applicative lowering recorded by the target-version fragments.
- Adds right-biased `Either` `Functor`/`Applicative`/`Monad`/`Foldable`/`Traversable` instances, generic `Foldable.fold_map`, and `Either.sequence`.
- Fixes MIR curried partial-application specialization so nested function-return parameters retain their concrete ABI; adds a pending-task continuation runtime and `Task.map`/`Task.and_then` without claiming an invalid ordinary `Monad` instance.
- Replaces Task's single continuation slot with an exactly-once multi-observer queue, adds cancellation/failure outcomes and propagation through `Task.map`/`Task.and_then`, and records waiter allocation/free counters for regression gates while continuing to withhold an ordinary `Monad` instance.
